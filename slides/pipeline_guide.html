RISC-Vプロセッサ 高速化の詳細解説

逐次実行 / 2段パイプライン / 5段パイプライン の仕組みと違い

0 実行時間の基本式
実行時間 = 実行命令数  ×  CPI  ×  クロック周期  ⟺  実行時間 = 実行命令数  ×  CPI  ÷  動作周波数
各項目の意味
  • 実行命令数：プログラムが実行する命令の総数（アルゴリズムで決まる）
  • CPI（Cycles Per Instruction）：1命令あたりの平均クロック数（アーキテクチャで決まる）
  • クロック周期：1クロックの長さ = 1 ÷ 周波数（回路設計で決まる）
高速化の手段
  • 命令数を減らす → アルゴリズム改善（選択→クイック）
  • CPIを下げる → スーパースカラ，OoO実行
  • 周波数を上げる → パイプライン化（クリティカルパス短縮）

※ パイプラインは周波数↑と引き換えにCPIも↑するトレードオフ

1 逐次実行CPU（シングルサイクル）

仕組み

1クロックで1命令すべてを処理するシングルサイクルCPU． デコード・ALU演算・メモリアクセス・ライトバックがすべて組み合わせ回路で構成され， クロックの立ち上がりでPCだけが更新される．

ソースコードで見る動作（quick_sort/riscv.v）

WB_RD_VAL は組み合わせ回路（330行）
// WB
always @( WB_MUX or DATAI or PC4 or E_RD_VAL )
  case( WB_MUX )
  2'b01:   WB_RD_VAL <= DATAI;    // Load
  2'b10:   WB_RD_VAL <= PC4;     // jal/jalr
  default: WB_RD_VAL <= E_RD_VAL; // ALU
  endcase

always @(...)（クロックなし）= 純粋な組み合わせ回路．
入力が変わればその瞬間に出力が確定する．

PC更新のみがレジスタ（FF）で同期（74行）
always @( posedge CLK or posedge RST )
  if( RST )
    PC <= 32'h0000_0000;
  else if( E_PC_E )
    PC <= BR_ADDR;  // 分岐・JAL・JALR
  else
    PC <= PC4;      // 通常: PC+4

FF（フリップフロップ）はPC1本のみ．毎クロック次命令へ進む．

分岐判定ロジック（ソースコード 287行）

assign E_PC_E = PC_E && !( ( FT == `FT_B ) && !ALU_RD_VAL[0] );
  • PC_E：JAL・JALR・条件分岐命令でセット
  • B型（条件分岐）：ALU_RD_VAL[0] が 1 のとき成立（IEQ/INE/ILT/… の結果ビット）
  • JAL・JALR：常に成立（PC_E=1かつB型でない）

なぜハザードが存在しないか

パイプラインレジスタが一切ない（PCを除く）ため，命令間の依存関係は問題にならない． WB_RD_VAL（書き戻し値）は組み合わせ回路で即座に確定しており， レジスタファイルへの書き込みと同クロックの読み出しが同時に完了するため データハザードが構造上発生しない． フォワーディング回路・ストール制御は実装されていない．

クリティカルパスとクロック周期の制限

最長経路：ロード命令（LW）

imem読み出し → デコード → ALU（アドレス計算）→ dmem読み出し → WB_RD_VAL確定
この全経路が1クロック内に収まる必要があり，周期 20 ns（50 MHz）が下限となる．

メモリ構成（ソースコード 8〜12行）

parameter IMEM_SIZE = 32768,  // 32kW = 128kB
parameter DMEM_SIZE = 32768,  // 32kW = 128kB
命令メモリ・データメモリ各 32kW（128kB）．Distributed RAM に展開されるため LUT消費が大きい（16,428 LUT = LUT全体の 86.46%）．

データフォワーディング（実装済み）

5段PLとの違い

5段PLでは EX→EX 間に 3サイクル の距離があるため，フォワーディング専用の配線（MUX）が必要になる．

2段PLではステージ間が 1サイクル だけで，EMWの WB_RD_VAL は組み合わせ回路なので，次サイクルの FD からそのまま参照できる．

→ 追加のフォワーディングMUXが不要

RV32M 乗算拡張（ソースコード 374〜388行）

MUL命令はMEMステージで計算（DSP48E1推論）
// MEMステージ: 乗算（DSP48E1推論のため $signed() で記述）
wire signed [63:0] MEM_MUL_SS = $signed(EX_MEM_RS1_VAL) * $signed(EX_MEM_STORE_VAL);
...
// DIV/REMは組み合わせ実装では周波数未達のため未実装（マルチサイクル化が必要）
default: MEM_MUL_RESULT = 32'h0;
  • MUL・MULH・MULHSU・MULHU の4命令を実装（RV32M サブセット）
  • 乗算器はEX/MEMレジスタから入力し，MEMステージ内の組み合わせ回路で計算
  • DIV・REM は未実装（組み合わせ実装では 12 ns クロック周期を達成できないため）
  • MUL結果は EX ステージでは未確定 → EX/MEM からの転送不可（後述）

ハザードの種類と対策（ソースコード 419〜442行）

① ALU→ALU データハザード

前命令のEX結果を次命令のEXが使う場合．

対策：フォワーディング（ストールなし）
EX/MEMレジスタの値を次命令のEX入力にバイパス転送する（経路②）．

② ロードユーズハザード（LOAD-USE）
wire LOAD_USE_HAZARD;
assign LOAD_USE_HAZARD =
  (ID_EX_WB_MUX == 2'b01) &&  // EXがLOAD命令
  (ID_EX_D_RD   != 5'b0)  &&  // RDが x0 でない
  ( ID_EX_D_RD == ID_RS1  ||
    ID_EX_D_RD == ID_RS2 );

LOADのメモリ読み出しはMEMステージまで完了しないためフォワーディング不可 → 1サイクルストール

③ MULユーズハザード（MUL-USE）
wire MUL_USE_HAZARD;
assign MUL_USE_HAZARD =
  ID_EX_IS_MUL &&         // EXがMUL命令
  (ID_EX_D_RD != 5'b0) &&
  ( ID_EX_D_RD == ID_RS1 ||
    ID_EX_D_RD == ID_RS2 );

wire STALL;
assign STALL = LOAD_USE_HAZARD || MUL_USE_HAZARD;

MUL結果はMEMステージで計算されるため EX/MEM からの転送不可 → 1サイクルストール

④ 制御ハザード（分岐命令）
// riscv.v 315〜317行
// FLUSH: 分岐成立 → IFとIDの命令をキャンセル
// （2サイクルペナルティ）
wire FLUSH;
assign FLUSH = EX_BRANCH_TAKEN;

分岐成立はEXステージで判明する．この時点で
・IF/ID レジスタ → NOP に上書き
・ID/EX レジスタ → NOP に上書き
の2段分をフラッシュするため 2サイクルペナルティ．

※ 2段PLは EX で分岐確定，FD→EMW の1段のみフラッシュで 1サイクルペナルティ．
5段PLは IF・ID の2段分あるため 2サイクルペナルティとなる．

3経路のデータフォワーディング（ソースコード 208〜282行）

✅ ソースコードに明示的に実装された3つのフォワーディング経路

経路① WB→ID フォワーディング（riscv.v 218〜221行）

// WBステージが書き込むレジスタをIDステージが同クロックで読む場合に転送
// （3命令差ハザード: WB値はFF出力から組み合わせで確定 → 同サイクル参照可）
assign ID_RS1_FWD = (WB_D_RD != 5'b0 && WB_D_RD == ID_RS1 && !ID_RS1_PC && !ID_RS1_Z)
                    ? WB_RD_VAL : ID_RF_DATA1;
assign ID_RS2_FWD = (WB_D_RD != 5'b0 && WB_D_RD == ID_RS2)
                    ? WB_RD_VAL : ID_RF_DATA2;

WB_RD_VAL は組み合わせ回路（always @(*)）で確定するため， レジスタファイル書き込みと同クロックの ID 読み出しに転送可能．

経路② EX/MEM→EX フォワーディング（riscv.v 261〜264行）

// FWD_A_SEL=01: EX/MEMのWB値を現在のEXに転送（2命令差ハザード）
// ※ LOAD命令（WB_MUX==01）とMUL命令は結果未確定のため除外
assign FWD_A_SEL =
  (EX_MEM_D_RD != 5'b0 && EX_MEM_D_RD == ID_EX_RS1_NUM
   && EX_MEM_WB_MUX != 2'b01 && !EX_MEM_IS_MUL) ? 2'b01 :  // ← ②
  (MEM_WB_D_RD != 5'b0 && MEM_WB_D_RD == ID_EX_RS1_NUM) ? 2'b10 :  // ← ③
  2'b00;

経路③ MEM/WB→EX フォワーディング（同 263行）

// FWD_A_SEL=10: MEM/WBのWB_RD_VAL（LOADの読み出し結果等）を転送
assign EX_FWD_A = (FWD_A_SEL == 2'b01) ? EX_MEM_WB_VAL :
                  (FWD_A_SEL == 2'b10) ? WB_RD_VAL      :  // ← ③
                                         ID_EX_RF_DATA1;

RS2 にも同様の FWD_B_SEL が実装されている（269〜282行）．

CPI増加の内訳（ハザード要因）

2段PL：CPI 1.1514（+15%）の原因
  • データハザード → フォワーディングでストールなし
  • 制御ハザード（分岐成立） → 1サイクルフラッシュのみ

CPI増加はすべて分岐命令によるフラッシュが原因

5段PL：CPI 1.3934（+39%）の原因
  • ALU→ALU ハザード → フォワーディングでストールなし
  • ロードユーズハザード → 1サイクルストール
  • MULユーズハザード → 1サイクルストール
  • 制御ハザード（分岐成立） → 2サイクルフラッシュ（2段PLの2倍）
結論
  • 実行時間最短：2段パイプライン（1.914 ms，1.24×）
  • 消費電力量最小：5段パイプライン（0.447 mJ，−51%）
  • 回路面積最小：5段パイプライン（LUT 3.65%）
  • パイプライン化は 周波数↑ と CPI↑ のトレードオフ——段数を増やせば必ず速くなるわけではない
  • 5段PLのエネルギ改善は主にメモリ削減（IMEM/DMEM 32kW→2kW）による消費電力低減が支配的
